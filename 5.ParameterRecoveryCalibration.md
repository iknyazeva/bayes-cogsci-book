## 1. Why Test Parameter Recovery Before Real Data Collection?

Before deploying a Bayesian model on empirical observations, researchers must verify that the mathematical structure and computational estimator can successfully learn the generating parameters when the truth is known with certainty.

**Parameter recovery** is a controlled experiment on your statistical estimator:
1. We choose or sample true parameters $\boldsymbol{\theta}_{\text{true}}$ from a prior or grid.
2. We simulate synthetic observations forward from the likelihood: $y_{\text{sim}} \sim p(y \mid \boldsymbol{\theta}_{\text{true}})$.
3. We fit the planned Bayesian model to the synthetic dataset to obtain the posterior $p(\boldsymbol{\theta} \mid y_{\text{sim}})$.
4. We compare the posterior center $\hat{\boldsymbol{\theta}}$ and credible interval $[L, U]$ directly against $\boldsymbol{\theta}_{\text{true}}$.

```{important}
**Recovery vs. Model Adequacy:**  
Good parameter recovery demonstrates that your model is **identifiable and your software implementation is correct**. It does *not* prove that the model describes the real world. A model can recover its generating coefficients perfectly in simulation while failing utterly to capture the empirical reality of human behavior. Real-world adequacy requires posterior predictive checking and domain validation.
```

## 2. The $45^\circ$ Diagonal Recovery Plot

In a repeated recovery study across $M = 100 \dots 1{,}000$ simulated datasets, we plot estimated posterior centers $\hat{\theta}^{(m)}$ (y-axis) against generating truths $\theta_{\text{true}}^{(m)}$ (x-axis), accompanied by the identity line $y = x$:

```
        θ̂ (Posterior Estimate)
          ▲
          │          .  /  (Ideal Recovery: hugs 45° diagonal)
          │            / .
          │           /. 
          │          /  .
          │       . /
          │        / .
          │       /
          └─────────────────────► θ_true (Known Generating Value)
```

### Diagnosing Pathologies on the Recovery Grid

| Visual Pattern | Underlying Statistical Pathology | Corrective Action |
|:---|:---|:---|
| **Points hug the $45^\circ$ line** | Estimator is unbiased; parameters are cleanly identified. | Proceed to design and power analysis. |
| **Consistent vertical shift above/below $y = x$** | Structural bias, indexing bug, or prior-data conflict. | Audit code for indexing offsets and likelihood sign errors. |
| **Horizontal flat cloud across x-axis** | **Non-identification**: Data contains zero information about $\theta$; posterior reflects only the prior. | Reparameterize model, introduce informative priors, or alter experimental design. |
| **Funnel shape (spread widens at large $\theta$)** | Heteroscedasticity or scale-dependent information (e.g. variance increasing with mean). | Check link functions or consider variance transformations. |
| **Slanted line with slope $< 1$ (attenuation)** | **Shrinkage**: Expected Bayesian shrinkage toward the prior mean under weakly informative priors. | Normal behavior; evaluate whether shrinkage improves out-of-sample RMSE. |

## 3. Overfitting, Flexible Models, and Bayesian Regularization

Simulation is indispensable for visualizing what occurs when a flexible statistical model is given the capacity to overfit empirical noise. Consider fitting a high-degree polynomial basis ($M = 9$) to $N = 12$ noisy observations:

1. **Unregularized MLE / Flat Prior**: The estimator chases idiosyncratic sample noise, oscillating wildly near boundaries (the Runge phenomenon) and producing catastrophic out-of-sample prediction errors.
2. **Bayesian Regularization (Gaussian Prior $\beta_j \sim \operatorname{Normal}(0, 1/\lambda)$)**: Placing a zero-centered prior on coefficients acts as a soft shrinkage mechanism, pulling high-order polynomial weights toward zero while retaining flexible curvature where data evidence demands it.

## 4. Calibration and Empirical 95% Coverage

A Bayesian credible interval is well-calibrated if, across many repetitions, nominal $100(1-\alpha)\%$ intervals contain the true parameter value with the declared probability:

$$
\widehat{C} = \frac{1}{M} \sum_{m=1}^M \mathbb{I}\left( L^{(m)} \le \theta_{\text{true}}^{(m)} \le U^{(m)} \right).
$$

### Two Regimes of Coverage Evaluation

1. **Fixed-Parameter Coverage**:  
   We fix $\theta_{\text{true}}$ at a specific constant (e.g. $\theta = 0.20$) and repeatedly generate synthetic datasets. This evaluates the **frequentist operating characteristic** of the Bayesian interval at that specific point in parameter space. Due to prior shrinkage, coverage may be slightly below nominal near extreme boundaries.
2. **Joint Model Calibration (Prior-Predictive Calibration)**:  
   We draw a new true parameter from the prior $\theta^{(m)} \sim p(\theta)$ for each simulation, then generate data $y^{(m)} \sim p(y \mid \theta^{(m)})$. When the generative model and analysis model match exactly, the Law of Total Probability guarantees that average empirical coverage across the joint space equals the nominal level ($95\%$) within Monte Carlo error.

### Monte Carlo Uncertainty of Coverage Audits

Because coverage is estimated from a finite number of simulations $M$, the empirical estimate $\widehat{C}$ carries Monte Carlo Standard Error (MCSE):

$$
\operatorname{MCSE}(\widehat{C}) = \sqrt{\frac{C(1 - C)}{M}}.
$$

* For $M = 1{,}000$ replications and nominal $C = 0.95$:
  $$\operatorname{MCSE}(\widehat{C}) = \sqrt{\frac{0.95 \times 0.05}{1{,}000}} \approx 0.0069 \quad (\approx 0.7\%).$$
* A 95% confidence interval for nominal coverage is $[93.6\%, 96.4\%]$. An empirical coverage of $94.1\%$ is well within expected simulation noise and does not indicate miscalibration!

## 5. Simulation-Based Calibration (SBC)

**Simulation-Based Calibration (SBC)** is a rigorous computational diagnostic that checks both the generative model and the MCMC sampling algorithm {cite}`talts2018validating`.

**Algorithm:**
1. Draw true parameters from the prior: $\boldsymbol{\theta}^* \sim p(\boldsymbol{\theta})$.
2. Simulate a full dataset: $y^* \sim p(y \mid \boldsymbol{\theta}^*)$.
3. Sample $L$ posterior draws using MCMC: $\boldsymbol{\theta}^{(1)}, \dots, \boldsymbol{\theta}^{(L)} \sim p(\boldsymbol{\theta} \mid y^*)$.
4. Compute the **rank statistic**: count how many posterior draws are smaller than the true value $\theta^*$:
   $$r = \sum_{l=1}^L \mathbb{I}\left( \theta^{(l)} < \theta^* \right) \in \{0, 1, \dots, L\}.$$
5. Repeat across $M = 1{,}000$ iterations and plot a histogram of the ranks $r$.

```
Rank Histogram Shapes & Diagnostic Interpretation:
┌─────────────────────┬─────────────────────┬─────────────────────┐
│      UNIFORM        │      U-SHAPED       │     HUMP-SHAPED     │
│   ┌─────────────┐   │   █         █       │          ▄█▄        │
│   │█████████████│   │   ██       ██       │        ▄█████▄      │
│   └─────────────┘   │   ██▄▄▄▄▄▄▄██       │      ▄█████████▄    │
│  Well-Calibrated    │   Overconfident     │   Underconfident    │
│  Correct posterior  │  Posterior too thin │ Posterior too broad │
└─────────────────────┴─────────────────────┴─────────────────────┘
```

* **Uniform**: The posterior accurately captures both location and uncertainty.
* **U-shaped**: The posterior is overconfident (variance is too narrow; true parameters fall into the extreme tails too often).
* **Hump-shaped**: The posterior is underconfident (credible intervals are excessively conservative).
* **Sloped (left or right)**: The estimator is systematically biased upward or downward.
