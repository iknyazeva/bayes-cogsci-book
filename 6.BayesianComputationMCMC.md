# Session 6: Bayesian Computation: Monte Carlo, MCMC, HMC and NUTS

## 1. The High-Dimensional Integration Problem

In simple 1-parameter conjugate models (such as the Beta-Binomial model in Session 4), the posterior distribution can be written in closed mathematical form. However, almost all applied statistical models—multiple regressions, hierarchical models, cognitive process architectures—involve vector parameters with dozens or hundreds of dimensions ($\boldsymbol{\theta} \in \mathbb{R}^D$ where $D \gg 1$).

To compute the posterior distribution, we must evaluate the normalizing constant (marginal likelihood):

$$p(y) = \int_{\mathbb{R}^D} p(y \mid \boldsymbol{\theta}) p(\boldsymbol{\theta}) d\boldsymbol{\theta}$$

In high dimensions, standard numerical quadrature (grid approximation) suffers from the **curse of dimensionality**: evaluating a grid with just 20 points per parameter across $D = 10$ dimensions requires $20^{10} \approx 10.24 \text{ trillion}$ function evaluations!

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       FROM INTEGRATION TO SIMULATION                        │
│ ─────────────────────────────────────────────────────────────────────────── │
│ Instead of computing the impossible integral p(y), modern Bayesian          │
│ computation draws S samples {θ^(1), θ^(2), ..., θ^(S)} directly from the    │
│ posterior distribution.                                                     │
│ Any posterior expectation E[g(θ)] is then approximated by a simple sample   │
│ average:                                                                    │
│                                                                             │
│               E[g(θ) | y] ≈ (1 / S) ∑_{s=1}^S g(θ^(s))                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

---

## 2. Monte Carlo Estimation & Monte Carlo Standard Error (MCSE)

By the Law of Large Numbers, as the number of simulated posterior draws $S \to \infty$, the sample mean of any function $g(\boldsymbol{\theta})$ converges to its true posterior expectation:

$$\bar{g}_S = \frac{1}{S} \sum_{s=1}^S g(\boldsymbol{\theta}^{(s)}) \xrightarrow{p} \mathbb{E}[g(\boldsymbol{\theta}) \mid y]$$

The uncertainty in our numerical approximation is quantified by the **Monte Carlo Standard Error (MCSE)**:

$$\text{MCSE}(\bar{g}_S) = \frac{\text{SD}(g(\boldsymbol{\theta}))}{\sqrt{S_{\text{eff}}}}$$

:::{important}
**MCSE vs. Posterior SD**:  
* **Posterior Standard Deviation ($\text{SD}(\theta)$)** measures substantive scientific uncertainty about the parameter $\theta$ given the sample data.
* **Monte Carlo Standard Error ($\text{MCSE}$)** measures numerical simulation noise due to drawing a finite number of samples $S$. We want $\text{MCSE}$ to be negligibly small (typically $< 1\%$ of $\text{SD}(\theta)$).
:::

---

## 3. Independent Monte Carlo vs. MCMC & Effective Sample Size

When draws are independent, $S_{\text{eff}} = S$. However, in high dimensions we must generate samples using a **Markov chain**, where each new draw $\boldsymbol{\theta}^{(s)}$ depends on the previous position $\boldsymbol{\theta}^{(s-1)}$.

Because adjacent draws are autocorrelated ($\rho_k = \text{Corr}(\theta^{(s)}, \theta^{(s+k)}) > 0$), a sequence of $S$ dependent MCMC draws contains less statistical information than $S$ independent draws.

### The Effective Sample Size (ESS):
$$\text{ESS} = \frac{S}{1 + 2 \sum_{k=1}^\infty \rho_k}$$

* If autocorrelation decays rapidly to zero ($\rho_k \approx 0$), $\text{ESS} \approx S$.
* If autocorrelation is severe ($\rho_1 = 0.95$), $\text{ESS}$ can be less than $5\%$ of total draws $S$, inflating $\text{MCSE}$.

## 4. Metropolis–Hastings: The Random-Walk Foundation

The **Metropolis-Hastings algorithm** provides the conceptual foundation of MCMC. Given an unnormalized target posterior $p^*(\boldsymbol{\theta}) = p(y \mid \boldsymbol{\theta}) p(\boldsymbol{\theta})$:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       METROPOLIS-HASTINGS ALGORITHM                         │
│ ─────────────────────────────────────────────────────────────────────────── │
│ 1. From current position θ^(s-1), propose a candidate:                      │
│                        θ* ~ Normal(θ^(s-1), σ_prop^2)                       │
│ 2. Compute the acceptance ratio:                                            │
│            α = min( 1, p*(θ*) / p*(θ^(s-1)) )                               │
│ 3. Accept θ* with probability α; otherwise stay at θ^(s-1).                 │
└─────────────────────────────────────────────────────────────────────────────┘
```

### The Proposal Tuning Dilemma:
* **Proposal Step Too Small ($\sigma_{\text{prop}} \ll 1$)**: High acceptance rate ($> 90\%$), but the chain crawls via slow Brownian diffusion, causing severe autocorrelation and tiny ESS.
* **Proposal Step Too Large ($\sigma_{\text{prop}} \gg 1$)**: The proposal almost always jumps into regions of low probability, causing high rejection rates ($> 95\%$) and sticky chains.
* **Why Random Walks Fail in High Dimensions**: In $D > 10$ dimensions, high-dimensional probability mass concentrates in a thin curved shell called the **Typical Set**. Blind random proposals almost always step outside this shell, causing random-walk MCMC to fail completely.

## 5. Hamiltonian Monte Carlo (HMC) & NUTS

To sample high-dimensional models efficiently, modern Bayesian software uses **Hamiltonian Monte Carlo (HMC)** and the **No-U-Turn Sampler (NUTS)** (*Hoffman & Gelman 2014*).

HMC converts sampling into the physics of a **frictionless particle gliding across a potential energy surface**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         HAMILTONIAN DYNAMICS IN MCMC                        │
│ ─────────────────────────────────────────────────────────────────────────── │
│ • Position Vector θ:    Parameter values (Potential Energy U(θ) = -log p(θ,y))│
│ • Momentum Vector p:    Auxiliary physical velocity (Kinetic Energy K(p))   │
│ • Gradient Vector ∇ log p(θ,y): Forces the particle along the typical set!  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### The Symplectic Leapfrog Integrator:
HMC uses the vector gradient of the log-posterior $\nabla_{\boldsymbol{\theta}} \log p(\boldsymbol{\theta}, y)$ to compute continuous, frictionless trajectories. Instead of taking blind random steps, the particle glides across the typical set over long distances in single leapfrog trajectories with acceptance rates $> 85\%$.

* **The No-U-Turn Sampler (NUTS)**: Automatically builds trajectory paths forward and backward in time, stopping adaptively as soon as the particle begins to turn back on itself, eliminating the need for manual trajectory tuning!

## 6. Modern Applied Workflow: PyMC 5 & ArviZ

In PyMC 5, specifying and sampling a Bayesian model requires only a clean declarative `with` block:

```python
import pymc as pm
import arviz as az

# 1. Define the probabilistic model
with pm.Model() as model:
    # Prior on latent parameter
    theta = pm.Beta("theta", alpha=5.0, beta=5.0)
    
    # Likelihood of observed data (k=16 out of N=20)
    y_obs = pm.Binomial("y_obs", n=20, p=theta, observed=16)
    
    # 2. Sample from posterior using NUTS
    idata = pm.sample(
        draws=1000,
        tune=1000,
        chains=4,
        random_seed=2026,
        return_inferencedata=True
    )

# 3. Summarize posterior and diagnostics
summary_table = az.summary(idata)
print(summary_table)
```

## 7. The Four-Point Minimum Computational Gate

Before interpreting any scientific results from an MCMC run, the analysis must pass the **Four-Point Minimum Computational Gate**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    THE 4-POINT MINIMUM COMPUTATIONAL GATE                   │
├──────────────────────────┬──────────────────────────────────────────────────┤
│ 1. Chain Replication     │ Run at least 4 independent chains (C ≥ 4) with   │
│                          │ dispersed starting points.                       │
├──────────────────────────┼──────────────────────────────────────────────────┤
│ 2. Convergence Metric    │ Rank-normalized R-hat < 1.01 (Vehtari et al.     │
│    (R-hat)               │ 2021) across all parameters and transformations. │
├──────────────────────────┼──────────────────────────────────────────────────┤
│ 3. Sample Efficiency     │ Bulk ESS > 400 (for means) and                   │
│    (Bulk / Tail ESS)     │ Tail ESS > 400 (for 95% interval quantiles).     │
├──────────────────────────┼──────────────────────────────────────────────────┤
│ 4. Geometric Health      │ ZERO divergent transitions (N_divergences = 0).   │
│    (Divergences)         │ Any divergence indicates un-sampled curvature!   │
└──────────────────────────┴──────────────────────────────────────────────────┘
```

## 9. Concept Check

````{dropdown} ❓ Why is rank-normalized R-hat preferred over historical R-hat?
Historical $\hat{R}$ (Gelman & Rubin 1992) relied on variance ratios assuming Gaussian posteriors. **Rank-normalized $\hat{R}$** (*Vehtari et al. 2021*) transforms draws to normal scores before computing variance ratios, allowing it to detect non-convergence in heavy-tailed, skewed, and multi-modal distributions where classical $\hat{R}$ fails.
````

````{dropdown} ❓ Does running a sampler for 1,000,000 iterations fix divergent transitions?
**No.** Divergences represent geometric singularities (regions of extreme curvature, such as Neal's Funnel) where the leapfrog integrator cannot follow the true Hamiltonian energy surface. Running longer simply encounters the failure region more times. The remedy is **reparameterization** (e.g. non-centered models) or increasing `target_accept`.
````

````{dropdown} ❓ Is thinning necessary in modern MCMC?
**No.** Thinning (discarding $k-1$ out of every $k$ draws) was invented in the 1990s to conserve computer hard drive storage. It does not improve estimation precision and discards valid posterior information. Modern Bayesian practice retains all post-warmup draws.
````
